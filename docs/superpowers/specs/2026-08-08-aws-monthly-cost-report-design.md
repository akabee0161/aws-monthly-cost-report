# AWS 月次コストレポート メール通知システム 設計書

- 作成日: 2026-08-08
- ステータス: 承認済み

## 1. 目的

AWS マネジメントコンソールを毎回開かずに済むよう、Cost Explorer API で前月1ヶ月分のコスト明細を取得し、月1回 E メールで通知する。

## 2. スコープ

### 対象

- 前月分の合計コストとサービス別内訳（上位10件）の取得
- 前月比（前々月との差分）の算出
- SNS 経由でのプレーンテキストメール通知
- 上記を AWS CDK (TypeScript) で IaC 管理

### 対象外

- 複数アカウント（Organizations）の横断集計
- 予算超過アラート（AWS Budgets の領域）
- タグ別・リージョン別の内訳
- HTML メール、Slack など他チャネルへの通知

## 3. アーキテクチャ

```
EventBridge Rule (cron: 0 0 5 * ? *  UTC = 毎月5日 09:00 JST)
        │ 非同期 invoke
        ▼
Lambda (Python) ──ce:GetCostAndUsage──▶ Cost Explorer (us-east-1 固定)
        │ sns:Publish
        ▼
SNS Topic ──▶ Email Subscription（確認メールの承認は手動）
```

正常時のレポートも異常時のエラー通知も、同一の SNS トピックへ Publish する。

### 3.1 リージョンに関する制約

Cost Explorer API のエンドポイントは `us-east-1` に固定されている。スタックのデプロイ先が `ap-northeast-1` であっても、Lambda 内では以下のように明示する。

```python
boto3.client("ce", region_name="us-east-1", config=Config(retries={...}))
```

SNS クライアントはスタックのデプロイ先リージョン（環境変数 `AWS_REGION`）をそのまま使う。

## 4. コンポーネント設計

### 4.1 Lambda モジュール構成

boto3 は Lambda ランタイムに同梱されているため、外部依存はゼロ。バンドル処理（Docker / pip install）は不要で、`lambda.Code.fromAsset` でソースディレクトリをそのまま同梱する。

```
lambda/
  cost_report/
    __init__.py
    handler.py          # エントリポイント: オーケストレーション + エラーハンドリング
    periods.py          # 期間計算（純粋関数）
    cost_explorer.py    # CE API 呼び出しとレスポンス正規化
    formatter.py        # 件名・本文の生成（純粋関数）
    notifier.py         # SNS Publish
```

Lambda ハンドラのパスは `cost_report.handler.lambda_handler`。

| モジュール | 入力 | 出力 | 依存 |
|---|---|---|---|
| `periods.py` | 基準日 (`date`) | `ReportPeriod`（前月・前々月の開始/終了日、CE クエリ全体の範囲） | なし |
| `cost_explorer.py` | `ReportPeriod`, CE クライアント | `MonthlyCost` × 2（合計、`{service: Decimal}`、通貨単位） | boto3 |
| `formatter.py` | `MonthlyCost` × 2、アカウント ID | 件名 `str`、本文 `str` | なし |
| `notifier.py` | トピック ARN、件名、本文、SNS クライアント | なし | boto3 |
| `handler.py` | Lambda event / context | ステータス dict | 上記すべて |

`periods.py` と `formatter.py` は AWS に依存しない純粋関数なので、単体テストが容易。

### 4.2 期間計算

Lambda は 00:00 UTC に起動する（= 09:00 JST 同日）。この時刻では UTC 日付と JST 日付が同一の月に属するため、UTC の `date.today()` を基準にして問題ない。

基準日が 2026-08-05 の場合:

| 項目 | 値 |
|---|---|
| 前月（レポート対象） | 2026-07-01 〜 2026-07-31 |
| 前々月（比較対象） | 2026-06-01 〜 2026-06-30 |
| CE クエリ `Start` | `2026-06-01` |
| CE クエリ `End` | `2026-08-01`（排他） |

年跨ぎ（1月実行時に前月=12月、前々月=11月）を単体テストで検証する。

### 4.3 Cost Explorer 呼び出し

2ヶ月分をまとめて 1 リクエストで取得する。CE API は 1 リクエストあたり $0.01 の課金があり、月次実行なら誤差だが、2回に分ける理由がない。

```python
ce.get_cost_and_usage(
    TimePeriod={"Start": "2026-06-01", "End": "2026-08-01"},  # End は排他
    Granularity="MONTHLY",
    Metrics=["UnblendedCost"],
    GroupBy=[{"Type": "DIMENSION", "Key": "SERVICE"}],
)
```

`ResultsByTime` が 2 要素返るので、`TimePeriod.Start` をキーに前月分・前々月分へ振り分ける。

正規化のルール:

- 金額は `Decimal(str(...))` で保持する。float に落とさない（表示時のみ丸める）。
- 通貨は決め打ちせず、レスポンスの `Unit` を採用する。
- ページネーション: `NextPageToken` が返る場合はループして全件取得する。サービス数が少なくても実装しておく。
- サービス別の金額が 0 の項目は内訳から除外する。

### 4.4 メール本文フォーマット

プレーンテキスト。

**SNS `Subject` の制約**: SNS の `Subject` パラメータは「ASCII テキストであること」「改行・制御文字を含まないこと」「100 文字未満であること」が要求される。したがって**件名は ASCII のみ**で構成する。`Message`（本文）にはこの制約がないため、本文は日本語で記述する。

**件名**

```
[AWS Cost] 2026-07 total 123.45 USD (+11.1%)
```

前月の合計が 0 の場合は率を省略する: `[AWS Cost] 2026-07 total 123.45 USD`

**本文**

```
============================================
 AWS 月次コストレポート
============================================
アカウント : 123456789012
対象期間   : 2026-07-01 〜 2026-07-31

■ 合計
  当月    : 123.45 USD
  前月    : 111.15 USD
  差分    : +12.30 USD (+11.1%)

■ サービス別内訳 (上位10件 / UnblendedCost)
  1. Amazon RDS                45.20 USD  (+2.10)
  2. Amazon EC2 - Compute      38.10 USD  (+9.80)
  3. Amazon S3                 12.55 USD  (-0.40)
  4. AWS Lambda                 8.30 USD  (+0.15)
  5. Amazon CloudWatch          6.90 USD  (+0.60)
  ...
  その他 (5件)                  3.15 USD

--
Generated by aws-monthly-cost-report
```

エッジケースの扱い:

| ケース | 表示 |
|---|---|
| 前月の合計が 0（前月比が計算不能） | 差分は金額のみ表示し、パーセンテージは `(前月 0.00 のため率は非表示)` とする |
| サービスが11件以上 | 上位10件を列挙し、残りを `その他 (N件)` に集約 |
| 前々月に存在しなかったサービス | 前月比は `(+全額)` ではなく差分金額をそのまま表示（`(+2.40)`） |
| コストデータが 0 件 | 「対象期間のコストデータがありません」を本文に出す（正常系として通知する） |

### 4.5 エラーハンドリング

要件は「API 取得失敗時も同じ SNS トピック経由でエラー通知を送る」。素直に「例外 → エラーメール → 再送出」とすると、Lambda 非同期呼び出しのデフォルト再試行（2回）によって同一のエラーメールが 3 通届く。これを避けるため、再試行の責務を Lambda 内部に閉じる。

1. boto3 クライアントに `retries={"mode": "standard", "max_attempts": 5}` を設定し、CE のスロットリング等の一時障害は Lambda 内で吸収する。
2. Lambda 関数の `retryAttempts` を `0` に設定する（非同期呼び出しの再試行を無効化）。
3. それでも失敗した場合、エラー内容を SNS へ 1 通だけ Publish し、その後に例外を再送出する。再送出により CloudWatch の `Errors` メトリクスに記録が残る。
4. エラー通知の Publish 自体が失敗した場合は、ログに出力したうえで元の例外を再送出する（エラー通知の失敗で元の原因を隠さない）。

エラーメールの件名（ASCII 制約のため英語）: `[AWS Cost][ERROR] monthly cost report failed`
本文（日本語）には例外クラス名、メッセージ、Lambda リクエスト ID、対象期間を含める。スタックトレース全文はメールに載せず CloudWatch Logs に出す。

なお `SNS_TOPIC_ARN` 環境変数が未設定の場合は、通知先が存在しないためエラー通知自体が送れない。この場合はハンドラ冒頭で `KeyError` を送出して CloudWatch に記録するに留める（デプロイ設定の誤りであり、CDK 側で必ず設定されるため実行時には発生しない）。

### 4.6 IAM 実行ロール（最小権限）

| 権限 | リソース | 理由 |
|---|---|---|
| `ce:GetCostAndUsage` | `*` | Cost Explorer はリソースレベルの権限指定をサポートしないため、`*` が最小 |
| `sns:Publish` | 本スタックが作成したトピックの ARN のみ | |
| `logs:CreateLogGroup`, `logs:CreateLogStream`, `logs:PutLogEvents` | Lambda のロググループ | `AWSLambdaBasicExecutionRole`（CDK が自動付与）。要件の `logs:*` より狭いのでこちらを採用 |

デプロイ自体は既存の AdministratorAccess の IAM ユーザーで行う。

### 4.7 CDK スタック構成

単一スタック `AwsMonthlyCostReportStack`。

| リソース | 設定 |
|---|---|
| `sns.Topic` | `displayName: "AWS Monthly Cost Report"` |
| `sns.Subscription` | Email。宛先は CDK context `notifyEmail` から取得 |
| `lambda.Function` | `Runtime.PYTHON_3_13`、`timeout: 60s`、`memorySize: 256MB`、`retryAttempts: 0`、環境変数 `SNS_TOPIC_ARN` / `TOP_N_SERVICES` |
| `logs.LogGroup` | 明示定義。`retention: ONE_MONTH`、`removalPolicy: DESTROY` |
| `events.Rule` | `schedule: cron(0 0 5 * ? *)` UTC |
| `events.LambdaFunction` ターゲット | 上記 Lambda |

デプロイ先の指定:

```typescript
env: {
  account: process.env.CDK_DEFAULT_ACCOUNT,
  region: process.env.CDK_DEFAULT_REGION ?? "ap-northeast-1",
}
```

`cdk deploy --profile <name>` でアカウントを切り替える。アカウント ID をリポジトリに残さない。

通知先メールアドレスはソースに埋め込まず、CDK context で渡す。

```
cdk deploy -c notifyEmail=you@example.com
```

未指定の場合は synth 時にエラーで停止させる（誤ってメール未設定のままデプロイされるのを防ぐ）。

## 5. テスト方針

| 対象 | 手法 |
|---|---|
| `periods.py` | pytest。月初/年跨ぎ/うるう年 |
| `formatter.py` | pytest。通常ケース、前月0、11件以上、データ0件 |
| `cost_explorer.py` | botocore Stubber でレスポンスを固定し、正規化とページネーションを検証 |
| `handler.py` | Stubber で CE 例外を注入し、エラー通知が 1 通だけ Publish され例外が再送出されることを検証 |
| CDK スタック | `aws-cdk-lib/assertions` の `Template`。cron 式、IAM ポリシー文、SNS サブスクリプション、`retryAttempts` を検証 |

Lambda のランタイムは Python 3.13 だが、ローカル環境の Python は 3.10 のため、Lambda 本体とテストコードは 3.10 で動作する構文に留める（`match` 文や `X | Y` 型注釈を使わない）。これによりローカルで pytest がそのまま動く。

## 7. 決定事項の記録

| 論点 | 決定 | 理由 |
|---|---|---|
| 実行日 | 毎月5日 09:00 JST | 3日時点では Savings Plans / RI の償却按分、AWS Support 料金、クレジット適用が未反映または変動する可能性がある |
| メール書式 | 標準（合計 + 前月比 + 上位10件） | 1画面で読み切れる情報量 |
| `env` 指定 | CLI プロファイル依存 | アカウント ID をソースに残さない |
| `logs:*` の縮小 | `AWSLambdaBasicExecutionRole` 相当の3アクションに縮小 | 最小権限の主旨に沿う。ユーザー承認済み |
| CE API の呼び出し回数 | 2ヶ月分を1リクエスト | リクエスト課金 $0.01/回、実装も単純 |
| 非同期再試行 | Lambda 側 `retryAttempts: 0` + boto3 内部リトライ | エラーメールの重複送信を防ぐ |
